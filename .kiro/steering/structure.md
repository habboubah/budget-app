# Project structure

`CLAUDE.md` is the full rulebook, feature by feature (charts, search, bank and Excel import, entry sheet order, categories per month, schema history, tokens, native plugins). Read the matching section before changing a feature area. This file is the map.

| Path | What |

## src/
| Path | Role |
|---|---|
| `main.tsx` | Boot: Dynamic Type, `hydrate()` the book before the first render, flush triggers, crash screen with a rescue export |
| `App.tsx` | Tabs, the pushed screen per tab, every sheet and dialog, toasts and undo, the lock |
| `store.ts` | `useAppStore()`: all state in `useState`, every mutation, view preferences in `localStorage` (`spartopf-*`) |
| `storage.ts` | The only module that reads or writes the user's data: an atomic, SHA-256-checked JSON file in the iOS app's Library (with a `localStorage` mirror), `localStorage` on the web; a debounced `saver` |
| `types.ts` | Data model: `Category`, `Entry`, `MonthRecord`, `Contract`, `AppData`, `Backup`, `EntryDraft` |
| `logic.ts` | Core pure logic: money parse / format, months, balances, carry-over, sorting, search, name suggestions, `normalizeState` / `upgradeData`, backup, CSV, `SCHEMA_VERSION`, `uid()` |
| `insights/` | Statistik and Planen, pure and tested per module: `buildBook()` (every entry read once), `usual()` and the thresholds, the series (D1), 50/30/20, hints ranked as `Insight` data, pace, Ausblick, Finanz-Check, category / payee detail, month report and year review; `index.ts` re-exports |
| `insightText.ts` | A hint in words for the view (translations in, a sentence out) |
| `budgets.ts`, `contracts.ts`, `due.ts`, `reminders.ts` | Pure domain modules behind budgets, contracts, the due list and the reminder plan |
| `statementImport.ts`, `excelImport.ts`, `xlsx.ts` | Bank CSV / OCR text import and Excel import |
| `notify.ts`, `lock.ts`, `ocr.ts`, `export.ts`, `platform.ts`, `dynamicType.ts` | Thin wrappers over native and browser APIs: notifications, Face ID, tesseract, file share / download, `isNative()`, text size |
| `translations.ts` | All UI text: flat `de` / `en` / `ar` objects, the `Strings` type, `fmt()` |
| `data/defaults.ts` | Built-in categories: names per language, emoji, hue, default repeat, name suggestions |
| `fixtures/` | What older versions stored and backed up (`storage-v*.json`, `backup-schema-*.json`), a demo year and its golden values |
| `components/` | `XxxView.tsx` screens, `XxxSheet.tsx` bottom-sheet forms, `XxxCard.tsx` cards, `Charts.tsx` |

## Architecture rules
- No router. `App.tsx` keeps `tab` (`month` | `stats` | `insights` | `settings`) and one pushed screen per tab (`stack[tab]`). A new pushed screen needs an id in `PushedId`, its parent tab in `PARENT`, and a case in `screenFor`.
- No state library and no context. State lives in `useAppStore()`; App passes data, callbacks, `t: Strings` and `language` down as props.
- User data (`AppData`) goes through `storage.ts` only. View preferences (language, theme, accent, folded cards) and device settings (reminders, lock) stay in `localStorage` via `store.ts` and are not part of a backup.
- Logic first: balances, sums, dates, imports and insights are pure functions in `src/*.ts` with tests. Components never do balance arithmetic.
- Money is integer cents (`Entry.amount`, never negative; the category's `kind` gives the sign). Convert only at the edges: `parseAmount()` in, `formatMoney*()` out, `normalizeDigits()` on typed input.
- Months are `MonthKey` strings (`YYYY-MM`, compare with `<` / `>`), days are `YYYY-MM-DD`. Use `addMonths()`, `monthKeyOf()`, `monthsEnding()`; never `Date` arithmetic in components.
- IDs come from `uid()` in the caller, never from the store.
- Updates are immutable. Optional fields set to `undefined` are deleted, not stored as `null`.
- Changing the data shape: new fields are optional; bump `SCHEMA_VERSION` in `logic.ts`; migrate in `normalizeState()` / `upgradeData()`; add a fixture to `src/fixtures/` so `compat.test.ts` covers it. Anything from storage or a backup passes `normalizeState()` first.
- Category ids are history: `fixed` = Wohnen, `extra` = Sonstiges (also where orphaned entries go). New built-ins go into `data/defaults.ts` with a migration; the extra banking-app categories ship with `standard: false`.
- Imports run parse → plan (pure data, shown in a preview sheet) → apply. Nothing is written before the user confirms.
- Destructive actions are undoable: `removeX()` in the store returns what it removed, `restoreX()` puts it back, and the toast offers Rückgängig. `Confirm` only where undo is impossible (delete all data, import a backup) or a lot goes at once.
- Screens compose `src/ui/` primitives instead of hand-rolled markup; tab screens use `<Screen tabbed>`, forms open in a `Sheet`.
- While locked, `App` renders only `LockScreen`, so no amount is in the DOM.

## i18n
- Every key goes into all three blocks of `translations.ts`; the `Strings` type is derived from `de`, so a missing key fails `npm run lint`. Placeholders are `{name}`, filled with `fmt()`.
- Never inline `language === 'de' ? …`. Money and dates format with `t.locale`.
- Built-in categories carry `names` per language; show any category name through `displayName(names, language)`.
- Arabic: `store.ts` sets `<html dir lang>`; Western digits; no count-dependent plurals ("البنود: {n}"); no letter-spacing.

## Workflow
- Done means `npm run check` passes. A money rule changed on purpose: re-record the golden year and say why in the commit. A screen changed: run `node scripts/ui-review.mjs --only <screens>` before and after.
- User-visible changes also update `README.md` (features), `CLAUDE.md` (rules) and What's New in `store/listing.md`.
- Ask before committing and before changing `ios/`. Release only when explicitly asked.
- Commit messages: one short, plain-English line about the feature, no conventional-commit prefixes (e.g. "Import bank transactions from a CSV export or a photo").
- Never commit real financial data (an .xlsx, a bank export, a screenshot) or `.env.release`, and never print the release credentials.
